# Zero-Shot 3D mIoU: First Measurements (2026-07-03)

## Instrument

`scripts/eval_miou_replica.py` on vMAP semantic Replica room_0 renders
(100 frames, seed 42). Semantics are evaluation-only — classification is
zero-shot by argmax over CLIP class-name queries (decoder route +
"a photo of a {name} in a room" template; see commit 26bcf31 for the
pathway ablation: encoder-latent 0.029 -> decoder 0.051 -> template 0.066).
SLAM maps are checkpointed; eval iterations take ~3 min.

## Scale ablation (single extraction scale)

| metric | whole | part |
|---|---|---|
| mIoU (20 classes) | 0.066 | 0.071 |
| ATE (cm) | 8.84 | 7.21 |

Per-class: part-scale helps compact distinct objects (lamp .13->.24,
vase .01->.17, wall .52->.72) but collapses large/architectural classes
(door .16->.03, table .11->.00, cabinet .11->.02) whose features
fragment into part-level semantics. Small-object classes (book, candle,
switch, picture) are zero at BOTH scales — 16-D features + any single
scale cannot represent them.

## Conclusions

1. Single-scale extraction ceilings at ~0.07 mIoU regardless of scale
   choice; the scales have complementary strengths.
2. The pipeline currently AVERAGES multiple scales into one feature
   field (`_extract_language_features`), which would blur rather than
   combine them. Genuine multi-scale needs per-scale feature fields with
   per-query max (LangSplat-style) — an architecture + VRAM decision
   deferred to the week-5 design window.
3. Numbers are NOT comparable to supervised semantic SLAM (SGS-SLAM
   ~0.9 trains on the labels); the honest paper framing is
   "open-vocabulary queryability without semantic supervision," with
   this metric tracking progress.
